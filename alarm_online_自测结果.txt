刀具故障确认器 alarm_online.py —— 自测结果（2026-09-03，v2）
================================================================

【用法】
  1) 建库（换刀/新工况积累后重跑）:
       python alarm_online.py fit
     -> alarm_library.joblib + alarm_library_meta.json
     库 = 全部正常周期 c3~12,14（121,151 行 x 316 列），fit 约 2 秒。
     阈值来源 = v2 行级 70/30 holdout 独立校准:
       WARN = p99 = 0.4997 | CRIT = p99.9 = 0.5723

  2) 对新 CSV 打分（前置条件: 该 CSV 已经过 标注+滚动特征 管线）:
       python alarm_online.py score --csv <path> [--out-prefix xxx] [--no-full]
     事件判定: 时间断层>10min 分段 | 瞬态屏蔽=段长30%(上限3min)
               | 主轴停转(L_spindle_speed<=0)行旁路，不参与事件
               | 连续>=10 行超 WARN 线 -> 事件 | 峰值超 CRIT 线则升级

【事件定性（详见 alarm_events_定性分析.txt）】
  * #1 (c6): 子程序切换 1103->1111 + 主轴 2799->4000 + Z 轴不动
    -> 工序切换过渡段，无害。可选优化：程序切换后短时屏蔽。
  * #2 (c7): 子程序切换 1111->1900(BAR CHAMFER 倒角) + Y 轴换位
    -> 工序切换过渡段，无害。
  * #3 (c14): 主轴负载 26916 vs 正常 2503（10.8 倍尖峰）+ 主轴降速
    + 主程序切换 -> 最值得现场确认的一个（撞刀/卡滞/重切削瞬态）。
  * 已知事件 #3(c13 坏柄段) 在加停转旁路后被过滤为 idle —— 该段本
    是"主轴已停"状态，报警语义由"故障确认"转为"状态监控"。若需要
    保留停转段报警（机床异常停转本身值得知道），可加 --no-idle-bypass。

【方法论沉淀（调试实录）】
  1. IForest 分数不可跨模型比较：库（fit 集）变化必须重新校准阈值，
     库与阈值一起生成一起用；换库后先复测分数再下结论。
  2. 固定时长 warmup 会把"比它短的突发段"整段吞掉（cycle13 坏柄段
     仅 2min15s、407 行高频突发，间隔中位 16ms，全被 3min warmup
     吞掉导致漏报）-> warmup 改为比例式（段长30%，上限3min）。
  3. 数据时间覆盖必须先查：71.9h 的周期只有 2 个时间点有数据行。
  4. 无监督异常的正确评估形态是「连续K行超阈 -> 事件」，不是累计率。

【部署注意】
  * n=1：仅一个坏柄事件验证；推广前需积累更多真实故障样本。
  * 换刀具型号/换料/改程序后必须重跑 fit 更新指纹库。
  * c6/c7 的工序切换过渡若要消除，可加"子程序切换后 N 秒屏蔽"，
    但注意 c14 的负载尖峰也伴随程序切换，勿把真异常一起屏蔽。
