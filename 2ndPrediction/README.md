## 一、这个目录是什么

项目主线（单刀 RUL 回归、5 档分档）已被两把刀的数据证伪。本目录是证伪之后的**落地替代方案**：

- 不再预测"还剩多少件"
- 只回答一个问题：**这把刀现在该不该换**
- 做法：**计数兜底 + 信号放行**（信号不做报警触发器，做"延长许可证"）

## 四、四个子命令

| 子命令 | 用途 | 什么时候用 |
|---|---|---|
| `eval` | 离线回测：对比现状 / 固定件数 / 纯计数 / 纯信号 / 两级报警 的成本 | 换参数后验证有没有变好 |
| `plan` | 输出每把刀的换刀件号执行表 | 制定换刀计划 |
| `scan` | 嵌套交叉验证，检查参数是不是碰运气选出来的 | 上线前必跑一次 |
| `online` | 指定一把刀，逐件回放并给出"立即换 / 可延长" | **车间每天用这个** |

```powershell
# 1. 回测（默认参数即可复现方案文档主表）
python bin_decision.py eval

# 2. 执行表（ρ=10，即一次失效 = 10 把刀）
python bin_decision.py plan --rho 10

# 3. 参数稳健性（约 30 秒）
python bin_decision.py scan

# 4. 单刀在线判定
python bin_decision.py online --prog 14 --cyc 27
python bin_decision.py online --prog 11 --cyc 41     # 短刀示例
```

## 五、规则（一句话）

```
加工到第 base×M0 件  →  查负载相对新刀基线是否上升 ≥ tau
    是（正常磨损路径）→ 放行延长，到 extend×M0 件再换
    否（异常路径）    → 立即换，不给延长
```

- **M0** = 同一程序其余刀寿命的中位数（留一刀口径）
- **基线** = 该刀前 K 件负载的中位数
- **信号** = 负载相对基线的升幅，取滑动 W 件中位数（抗单件噪声）

### 默认参数

| 参数 | 默认 | 含义 |
|---|---|---|
| `--base` | 0.40 | 基准点 = 40% × M0 件时触发检查 |
| `--extend` | 0.90 | 判健康则延长到 90% × M0 件 |
| `--tau` | 0.01 | 信号阈值：相对基线上升 ≥1% 判正常磨损 |
| `--K` | 20 | 新刀基线窗口件数 |
| `--W` | 10 | 信号平滑窗口件数 |
| `--rho` | 2,5,10,20,50 | 一次失效折合几把刀（**待你提供真实值**） |

## 六、实测结果（16 把刀，留一刀口径）

| 策略 | 加工件数 | 失效 | 成本(ρ=10) |
|---|---|---|---|
| 现状：用到失效才换 | 1538 | 16/16 | 0.1144 |
| 固定 70 件（Weibull N*） | 1059 | 3/16 | 0.0434 |
| 纯计数 40%M0 | 598 | **0**/16 | 0.0268 |
| **两级 40%→90% τ=1%（推荐）** | **934** | **0**/16 | **0.0171** |
| 纯信号 τ=1% | 688 | 4/16 | 0.0814 |

**比现状改善 6.68 倍；比纯计数多加工 56%，同样是 0 失效。**
成本**不随 ρ 变化**（因为 0 失效），所以无论失效多贵都是最优。

> ⚠️ 脚本输出的 934 件与方案文档的 937 件差 3 件，原因是脚本把换刀件号取整为整数（文档用浮点累加）。成本结论完全一致。

## 七、上线前必读的三条限制

1. **ρ 还是假设值。** 需要你给：一把刀价格、一次失效损失（工件报废+停机+检修）、换刀停机时间。
   ρ≥5 用 40%→90%；ρ≤2 可用 50%→90%（多加工 137 件，代价 1/16 失效）。

2. **短刀只有 3 把，这是最大软肋。** 二元规则的 Fisher 检验 p=0.15（不显著）。
   但风险结构是安全的：**判"延长"的 7 把刀里短刀 0 把 → 假阴性=0**，延长动作不会造成失效；
   假阳性 6 把只是浪费寿命，不出事故。**可以上线，但要专门收集短刀样本来验证。**

3. **只验证过 T1111（4152 / L 通道 / 切断刀）。**
   另一把刀 T3434（2428 / R 通道 / 外径刀）已独立验证为**不可行**（寿命 CV=0.632、信号 |r|≤0.12）。
   换设备/换工序前必须重跑 `eval` 和 `scan`。

## 八、附：为什么"信号"在这个方案里不用来触发报警

三次独立的分档实验（3 档 / 5 档 / 2 档）都得到同一个结果：**把磨损信号加进来做触发器，准确率不升反降**。

原因是每把刀的信号方向不一致（16 把刀里 5 把反向），跨刀合并出的斜率对新刀经常是错的。

真正稳定的是**方向**而不是数值：

- 负载**正常上升** → 这把刀长寿（斜率 vs 寿命/M0：Spearman **+0.817, p=0.0001**）
- 负载**不升反降** → 短命（短刀 c41 −0.027 / c25 −0.047 / c37 +0.005）

所以信号的正确用法是**"延长许可证"**：计数负责兜底（绝不失效），信号负责放行（少浪费寿命）。
这是本轮相对此前所有尝试最大的思路转变。
