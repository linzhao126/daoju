## §2　B1：Test-D 崩刃时间截断

### 2.1 病灶（审核 P0-02 说对了）

```python
nh = max(TPL, int(len(score) * HEALTH_FRAC))   # 参考段长度依赖最终周期长度
```

参考段（定阈值 `mu/sd` 的"健康段"）长度由**最终周期长度**决定 → 删掉后半段数据，阈值就变了，前 N 件判定跟着变。

### 2.2 改法

```python
REF_FIXED = 30                      # 参考段固定 30 件
nh = min(REF_FIXED, len(score))     # 与周期总长无关
```

同时给 `cycle_score(c, N)` 加**按件序号截断**（不是按"前 N 个有效段" —— 某件判废时后者会滑到第 N+1 件，`hi_asof` 曾踩过同一坑）。

### 2.3 结果：9/9 PASS

| 周期 | 件数 | N=40 | N=60 | N=80 |
|---|---|---|---|---|
| c30 | 109 | PASS | PASS | PASS |
| c33 | 107 | PASS | PASS | PASS |
| c38 | 197 | PASS | PASS | PASS |

| 指标 | 值 |
|---|---|
| 最大 \|Δscore\| | **0.000e+00** |
| 最大 \|Δthr\| | **0.000e+00** |
| `nh` 一致性 | 全部 30/30 |
| 事件越界 | **0** |

### 2.4 副作用：检出率从 1.0 降到 0.8

固定参考段比"按 25% 取值"更严格，检出率下降：

| 指标 | 修复前 | 修复后 |
|---|---|---|
| 弱标签覆盖率（破损周期） | 11/11 = 1.00 | **12/15 = 0.80** |
| 磨损对照也报警 | 2/2 = 1.00 | 2/2 = 1.00 |
| 候选密度（次/日历小时） | 0.18 | 0.16 |

**特异性仍是 0**（磨损对照 2/2 照报），结论不变：**崩刃检测不能上线**。

## §3　B2：Test-E 换刀检测不读 life_cycle（本轮最重要的发现）

### 3.1 病灶：循环论证

```python
cross = B[B.cross_cycle]        # ← cross_cycle 由 life_cycle 变化定义
innr  = B[~B.cross_cycle]
tp = (cross.gap_s > thr).sum()  # ← TP 直接来自标签
fp = (innr.gap_s > thr).sum()
```

报告里写"可部署口径：只看 gap，不看标签"，**代码里 TP/FP 恰恰是按标签分的**。

### 3.2 改法（四处）

| # | 改动 |
|---|---|
| 1 | 候选 = `gap > 阈值`（纯数据）；TP/FP 由 `is_true_switch`（台账 `EndTime ± 30min`）判定 |
| 2 | 真值筛选从 `have_cyc = set(d.life_cycle)` 改为**"台账窗内是否有数据行"**（纯时间判定） |
| 3 | 修 `E_sorted` 排序后 `truth.cycle.values[k]` 未同步的错配 bug（审核 P0-03 附带） |
| 4 | `main(blank_cycle=...)` 参数化，供 Test-E 对照 |

### 3.3 结果：46/46 PASS，但 AUC 崩了

| 指标 | 正常 | life_cycle 全置 0 | Δ |
|---|---|---|---|
| AUC(gap) | 0.559932 | 0.559932 | **0.0** |
| AUC(\|Δload\|) | 0.512161 | 0.512161 | 0.0 |
| 真值数 / 断点数 | 19 / 1744 | 19 / 1744 | 0.0 |
| 40 个曲线点位（tp/fp/prec/rec × 10 阈值） | — | — | 全部 0.0 |

**指标完全不依赖 `life_cycle`，可部署口径成立。**

### 3.4 ⚠ 但真正的结论是：AUC 从 0.862 掉到 0.560

| 项 | 原口径（用 `life_cycle` 分 TP/FP） | 新口径（只用台账时间） |
|---|---|---|
| **AUC(gap)** | **0.862** | **0.560**（≈随机） |
| 阈值 15min 精确率 | — | **0.152** |
| 阈值 1h 精确率 | 0.211 | **0.053** |
| 阈值 1h 召回率 | 0.211 | 0.053 |

**为什么原版"看起来有点像"**：`life_cycle` 变化的断点，gap 天然大于同周期内断点（换刀确实比件间空档长）。但这正是标签定义的结论，**不能用来预测标签**。

**新口径的真相**：

| | 换刀断点 | 周期内断点 |
|---|---|---|
| gap 中位 | **5 分钟** | **5 分钟** |
| 范围 | 4.3 min ~ 1.2 h | p90 5.4 min，max 218.7 h |

**两者分布几乎完全重叠，没有任何阈值能分开。**

> 这条比"精确率只有 21%"严重得多：
> 原来的说法是"能检出，但误报多"；**真实情况是"连区分力都没有"**（AUC 0.56 ≈ 抛硬币）。

已同步更正 `15_台账真值检验/15-00`（§2.2 表、§2.3 标题与说明、新增 §2.4 新旧口径对照、结论句）。

## §4　D1：P1-03 bootstrap 按刀聚类

### 4.1 病灶

```python
bs = [d0.sample(len(d0), replace=True).mean() for _ in range(2000)]
```

`d0` 是"每把刀 × 每个截断点"的行，同一把刀在 4 个截断点各出现一次 → **按行重采样等于把同一把刀重复计入**，CI 被低估（偏窄，容易假阳性）。

### 4.2 改法

```python
_tmp = okall.assign(_diff=d0, _tool=prog + '-c' + cycle)
per_tool = _tmp.groupby('_tool')['_diff'].mean()      # 每把刀先算平均
bs = [per_tool.sample(len(per_tool), replace=True).mean() for _ in range(2000)]
```

### 4.3 结果

| 版本 | CI | 说明 |
|---|---|---|
| 按行（原） | 更窄 | 假阳性风险 |
| **按刀聚类（新）** | **[-1.65, +0.56]** | n_刀=12 / n_行=43，**跨 0（无显著差异）** |

## §5　D3：P1-02 候选密度改名

### 5.1 病灶

`s25` 的 `hours = (t1 - t0) / 3600` 是**日历跨度**（首件→末件墙钟时间），包含停机/交接班/夜间。但指标名叫「**误报密度(次/切削小时)**」。

### 5.2 改法

| 原 | 新 | 理由 |
|---|---|---|
| 列 `CuttingHours` | `CalendarHours` | 分母不是切削时间 |
| 列 `FA_perHour` | `CandPerCalHour` | 同上 |
| 指标「误报密度(次/切削小时)」 | 「**候选密度(次/日历小时)**」 | 分母语义 + 无独立阴性标签，不能说"误报" |
| 指标「误报密度(次/千件)」 | 「**候选密度(次/千件)**」 | 同上 |

### 5.3 结果

```
候选密度(次/日历小时)   0.16   n=17   分母是首件→末件的墙钟时间，含停机/交接班；非切削时间
候选密度(次/千件)      23.9   n=17   候选区间数 / 件数 ×1000；不能用"误报"命名——无独立阴性标签
```

## §6　C3：P0-06 BoundaryEvidence 重建

### 6.1 病灶

```python
def boundary(r):
    if r.DataQualityGrade == 'D': return 'DATA_EDGE_OR_FROZEN'
    if r.PhysicalLifeId.endswith('c38'): return 'LEDGER_OPEN(...)'   # ← 硬编码
    if r.LeftTruncated: return 'DATA_EDGE(数据起点)'
    return 'LEDGER_EXACT'      # ← 其余全默认赋值，等于没验证
```

### 6.2 改法：按实测边界差分级

读 `23_两批数据等价性/L2_by_window.csv`（数据实际起止 vs 台账窗起止），逐周期算 `d0`（起点差）、`d1`（止点差），阈值 60 分钟：

| 分级 | 判据 |
|---|---|
| `DATA_EDGE_OR_FROZEN` | DQ = D |
| `BOTH_TRUNCATED` | d0 > 60 且 d1 < −60 |
| `LATE_START` | d0 > 60（缺前段） |
| `EARLY_STOP` | d1 < −60（提前停） |
| `LEDGER_EXACT` | 两端都 ≤60，**并带实测值** |
| `UNVERIFIED` | 无实测数据，不下结论 |

### 6.3 结果：19 个周期全部有实测依据

| 分级 | 周期数 | 周期 |
|---|---|---|
| DATA_EDGE_OR_FROZEN | 3 | c16、c42、c45 |
| EARLY_STOP | 3 | c32（−63min）、c36（−661min）、c41（−1216min） |
| LATE_START | 2 | c25（+1100min）、c37（+254min） |
| LEDGER_EXACT（带实测值） | **11** | 其余，如 c30 `(+6,−3)`、c38 `(+5,−13)` |

**c38 不再硬编码**，现在是 `LEDGER_EXACT(d0=+5,d1=-13 min)` —— **边界其实吻合得很好**，它的问题从来不是边界，而是**件数**（197 vs 台账 102）。

这同时纠正了一个此前的误判：`21-00` 曾说「c38 边界未闭合」，实际边界正常，异常在件数。
