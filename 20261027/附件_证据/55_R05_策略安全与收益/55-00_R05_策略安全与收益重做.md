## §0　五句结论

1. **收益高度依赖崩刃位置，不是常数**：ρ=10 时，若刀在 100% 才失效（θ=1.0），两档成本 **0.0316** 只有现状 0.1161 的 27%；若崩在 50%（θ=0.5），两档 0.1825 vs 现状 0.2323，**只省 21%**。**"6.7 倍"只在"刀能活到台账终点"这个世界里成立。**
2. **在这张表的口径下（θ 固定、每周期一把刀），ρ≥2 时纯计数 40% 最便宜**（θ=0.8、ρ=10：0.0279 vs 两档 0.0810）。原因是它从不超期（失效 0 次），代价是浪费产能。
   ⚠ **2026-10-29 晚补正**：这个结论只对"θ=0.8"（≈崩刃后还做 20 件才发现）成立。按「同样产出 2179 件」折算后（`s57` + `62-00 附录A`），k=1~5 件时纯计数的门槛是 **ρ≈3.5~5**，不是 2。**双轴表以 `62-00 附录A` §1.4 为准。**
3. **滞回（连续 3 件确认）在 ρ=10 这个点上更差**：放行 12→15 把、带病 87→101 件、成本 0.0810→0.0824。
   ⚠ **晚补正**：滞回并非全面更差——按同产出折算，**ρ 在 1.3~2.3 区间时滞回反而略优**（它每把刀多出 5 件产出）。所以正确表述是「**滞回只在失效代价中等时有用，ρ 大时不如锁存**」；`60-00 附录E` §7 的"方向正确"仍不成立，但"实测更差"也只在 ρ=10 成立。见 `62-00 附录A` §1.4。
4. **实测上线观察：没有。** 线上库 `tool_events` **0 行**、`pieces` **100 行全是仿真**、`kv` 3 条。规则从未在真实产线上跑过一件。**本文件全部是离线回放，不是上线观察。**
5. **真实失效证据缺口仍在**：台账 `是否真实失效` 60/60 全填"是"，物理崩刃时刻在数据里不存在。**因此"零崩刃/零失效"这类表述在本文一律不出现，也不能出现在任何汇报里。**

## §1　方法

| 项 | 定义 |
|---|---|
| 周期 | 23 个可判（28 个 HI 周期中，5 个同主程序历史 <3 把被排除：c33/c55/c56/c57/c58） |
| `Life` | 台账换刀点件数（与观测件数一致的周期） |
| 规则输出 `Limit` | 允许这把刀用到第几件 |
| θ | 假设真实崩刃发生在 θ·Life。θ=1.0 = 直到台账换刀点都没崩 |
| 合格产出 | Σ min(Limit, θ·Life) |
| 带病加工 | Σ max(0, min(Limit,Life) − θ·Life) ← **崩了还在用** |
| 失效次数 | #(Limit > θ·Life)；`STATUS_QUO` 按"换刀即失效"记满 |
| 成本 | (刀数 + ρ×失效次数) / 合格产出，刀数 = 23 |

五条规则：

| 代号 | 含义 |
|---|---|
`STATUS_QUO` | 用到台账终点（现状）
`COUNT_B` | 纯计数，一律 0.4·M0 就换
`COUNT_H` | 纯计数，一律 0.9·M0 就换
`TWO_STAGE` | 线上现行：HI 在 b 处升 ≥1% → 用到 0.9·M0，否则 0.4·M0（**锁存一次**）
`TWO_STAGE_HYST` | 同上，但要求 b 之后**连续 3 件** hi_now ≥ 1+TAU

## §2　崩刃位置敏感性（`R05_replay_by_theta.csv`）

### 2.1 件数（23 个周期合计）

| 规则 | θ=0.8 合格 / 带病 / 失效 | θ=1.0 合格 / 带病 / 失效 |
|---|---|---|
| STATUS_QUO | 1744 / **435** / 23 | 2179 / 0 / 23 |
| COUNT_B | 824 / 0 / 0 | 824 / 0 / 0 |
| COUNT_H | 1574 / **177** / 16 | 1751 / 0 / 0 |
| **TWO_STAGE** | 1272 / **87** / 8 | 1359 / 0 / **2** |
| TWO_STAGE_HYST | 1372 / 101 / 9 | 1473 / 0 / 3 |

**读法**：
- 现状在 θ=0.8 时 **435 件带病**——这就是"0/16 失效"掩盖掉的东西。
- 两档把带病压到 **87 件**（降 80%），但合格产出从 1744 掉到 1272（**−472 件产能**）。
- 两档在 θ=1.0 仍有 **2 次失效**（c38、c51 —— 那两把寿命 197/170，远超 0.9·M0）。

### 2.2 成本（ρ=10，`R05_cost_rho.csv`）

| 规则 | θ=0.5 | θ=0.6 | θ=0.7 | θ=0.8 | θ=0.9 | θ=1.0 |
|---|---|---|---|---|---|---|
| STATUS_QUO | 0.2323 | 0.1939 | 0.1661 | 0.1451 | 0.1291 | 0.1161 |
| COUNT_B | **0.0792** | **0.0654** | **0.0401** | **0.0279** | **0.0279** | 0.0279 |
| COUNT_H | 0.2206 | 0.1887 | 0.1577 | 0.1163 | 0.0788 | **0.0131** |
| TWO_STAGE | 0.1825 | 0.1529 | 0.1129 | 0.0810 | 0.0473 | 0.0316 |
| TWO_STAGE_HYST | 0.1967 | 0.1717 | 0.1291 | 0.0824 | 0.0508 | 0.0360 |

**三个必须一起说的结论**：

1. **"两档 vs 现状"的倍数随 θ 从 1.27 倍（θ=0.5）变到 3.7 倍（θ=1.0）**。`47-00` 报的 6.7 倍是 16 周期 + 另一套成本公式的结果，与本表不可直接比；**任何引用倍数的地方必须同时给 θ。**
2. **COUNT_B 全程最便宜**，因为它失效 0 次。它的代价是产能：θ=1.0 时它只产出 824 件，两档 1359 件，现状 2179 件。**所以"哪个便宜"完全取决于"一件产能值多少钱"——这就是 ρ 的另一半，本数据里没有。**
3. **θ=1.0 时 COUNT_H 比两档还便宜**（0.0131 vs 0.0316）：如果刀真的都能活到 90%，信号分支纯属自找麻烦。

## §3　ρ 敏感性

完整矩阵见 `R05_cost_rho.csv`（5 规则 × 6 θ × 6 ρ = 180 行）。摘 θ=0.8：

| ρ | STATUS_QUO | COUNT_B | COUNT_H | TWO_STAGE | HYST |
|---|---|---|---|---|---|
| 1 | 0.0264 | 0.0279 | 0.0248 | 0.0244 | **0.0233** |
| 2 | 0.0396 | **0.0279** | 0.0349 | 0.0307 | 0.0299 |
| 5 | 0.0791 | **0.0279** | 0.0654 | 0.0495 | 0.0496 |
| 10 | 0.1451 | **0.0279** | 0.1163 | 0.0810 | 0.0824 |
| 20 | 0.2769 | **0.0279** | 0.2179 | 0.1439 | 0.1480 |
| 50 | 0.6726 | **0.0279** | 0.5229 | 0.3325 | 0.3448 |

**交叉点只有一处，在 ρ≈1.5**：
- **ρ ≤ 1**（失效几乎不花钱，产能最要紧）→ **两档/滞回最便宜**（0.0233~0.0244），**现状反而最贵**（0.0264）——因为现状每把刀都记一次失效，23 次失效的刀数成本已经超过省下的产能；
- **ρ ≥ 2** → **COUNT_B 恒定最便宜**（0.0279，不随 ρ 变，因为它从不超期）；
- **STATUS_QUO 在 θ=0.8 下任何 ρ 都不是最优。**

**这张表是 R05 唯一能拿去做决策的东西**：ρ 一旦由 0 号位给出，规则选择就变成查表，不需要再讨论"信号有没有用"。

⚠ **本表不能跨 θ 混用**：ρ 相同的条件下，θ 从 0.5 挪到 1.0，两档成本会从 0.1825 掉到 0.0316（6 倍）。**报"哪条规则更省"必须同时报 (θ, ρ) 两个坐标。**

## §4　误报与放行质量（`R05_grant_quality.csv`）

| 判定 | 现行锁存 | 滞回（连续 3 件） |
|---|---|---|
| 放行 | 12 把 | 15 把 |
| 放行中真的活过 0.9·M0 | **10（83%）** | 12（80%） |
| **误放行**（放行了但没活到） | **2（17%）** | 3（20%） |
| 拦截 | 11 把 | 8 把 |
| 拦截中本可活过 0.9·M0 | **6（55%）** | 4（50%） |
| **误拦截** | **6（55%）** | 4（50%） |

**误拦截比误放行严重得多**：11 把被拦的刀里 6 把本来能多干 30~40 件。这与 `60-00 附录E` §2 一致，也是"信号分支整体上在浪费产能"的原因。

**滞回只把结论改动了 3 把刀（c36 / c39 / c53）**，两把是"原本拦、现在放"。代价见 §2.1：带病 87→101 件。**所以我不再推荐滞回方案。**（`60-00 附录E` §7 表中原写"方向正确"，此处撤回。）

审核 `P0-MOD-03` 要求跨程序刀龄累计；`60-00 附录F` 提出按 Σ(pᵢ/M0ᵢ) 折算。这里量化"只数当前程序"会错多少：

| c27 | 6@14 + 92@20 | 98 | 0.860 | 0.960 | **10.0 pp** |
| c34 | 41@19 + 76@14 | 117 | 0.894 | **1.432** | **53.8 pp** |
| c38 | 195@14 + 2@11 | 197 | 0.024 | **2.461** | **243.7 pp** |

**c34 这一行就是"会直接把刀用崩"的量级**：系统看到"用掉 89%"，实际已用掉 143%。
（`60-00 附录F` §3.1 报的 38 pp 是按 `76/82.5` 算的；这里按"当前程序 = 最后一段"重算得 53.8 pp，两个数都对，取哪个取决于"当前程序"怎么定义——**线上取的是最后一件的程序**，所以用 53.8。）
