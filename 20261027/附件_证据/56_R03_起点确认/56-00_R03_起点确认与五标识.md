## §1　起点确认（`ToolLifeStartConfirmed`）

### 1.1 判定链

```
last_new   = SELECT allnum FROM tool_events WHERE event='new' ORDER BY id DESC LIMIT 1
base_allnum = last_new.allnum if last_new else min_allnum - 1
start_confirmed = (last_new is not None)          ← 新增
judge_ok    = (m0 is not None and p85 is not None)   ← 原语义保留（样本够）
judge_allowed = judge_ok and start_confirmed         ← 新增：判定资格
```

**为什么不直接把 `judge_ok` 改严**：`judge_ok` 还控制四格统计（最短/中位/最长/常见上限）的显示。样本够就该显示统计，只是不许给判定。两个概念混在一个字段里，就会出现"历史够但起点不明 → 连统计都不显示"的新问题。

### 1.2 冷启动时的行为（这是行为变更，必须说清）

| 项 | 改前 | 改后 |
|---|---|---|
| `used` | 报全量 | 报全量（不变） |
| 页面件数 | `≥N` | `≥N`（不变） |
| `b` / `h` / `limit` | **照常给出** | **`None`** |
| `state` | ok/chk/sug/bad | **`cnt`** |
| 页面文案 | 「距复核点还有 N 件」 | 「本刀起点未确认（冷启动）· 件数 ≥N 是下限 · 不做换刀判定」 |

⚠ **当前线上库 `tool_events` 是 0 行** → **升级后页面所有刀都会落到 `cnt`，一个判定都不给。** 这是故意的，也是审核要求的方向；要恢复判定，必须在装刀时点一次「换新刀」（这是"发令换刀"架构需要的那一次点击，不是台账）。

⚠ **这不是"回测过的影子模式"**。审核原文要求"先以影子模式回测"——回测需要真实的起点确认记录，而线上一条都没有。**本轮只能交"门禁已加"，不能交"影子回测已完成"。**

## §2　五个标识分离（`P0-MOD-03`）

| 审核要求的名字 | 本实现 | 代码位置 |
|---|---|---|
| `PhysicalToolLifeId` | `phys_life_id = "phys_%s_%d" % (TOOL_NO, base_allnum)` | `compute_view()` 内，`used` 之后 |
| `ProgramSegmentId` / `PartSegmentId` | `segment_id = "p%d" % prog`、`base_segment_id = "p%d" % 首段程序` | 返回体 |
| `ToolInvocationIndex` | `tool_invocation_index = n_segments`（**连续程序段数**） | 同上 |
| `ObservedPieceCount` | `used = COUNT(*) WHERE allnum > base_allnum`（**不加程序过滤**） | 60-00 附录D 已改 |
| `ExposureBySegment` | `exposure_by_segment = [{seg, prog, pieces}, ...]`，**合计 == used** | 新增 |

### 2.1 为什么 `tool_invocation_index` 用"连续段数"而不是 `distinct prog`

`11→20→11` 这段加工：`distinct prog` = 2，但**实际调用了 3 次**（两次回程序 11）。用 distinct 会把"回到原程序"这件事吞掉，而锁存/基线恰恰要按"段"来判断。

实现：按 `allnum` 顺序扫 `pieces.prog`，相邻不等就 +1。测试 T5.4 专门守这一条。

## §4　续设不归零（`test_g` T7）

**场景**：台账/人工把 `tool_life` 上调（续设，不是换刀）。在旧实现里这不会触发 `tool_events.new`，所以 `base_allnum` 不动——但要证明，不能只靠"读代码觉得没问题"。

| 断言 | 结果 |
|---|---|
| T7.1 `used` 不变 | ✅ 70 → 70 |
| T7.2 `base_allnum` 不变（续设 ≠ 换刀） | ✅ 0 → 0 |
| T7.3 物理刃口 ID 不变 | ✅ |
| T7.4 M0 会随历史更新，但**判定资格不变** | ✅ |

**旁注**：`history` 里加了 `src='手工续设'` 的两条（life 200/250），会让 M0 变粗。当前 `history` 没有字段区分"真实换刀寿命"与"人工续设值"——**这是下一轮要补的（`tool_life` 表 `source` 枚举）**，本轮只保证"续设不影响刀龄"。

## §5　`MONITOR_ONLY` 与 `safety_permit`

| 字段 | 值 | 含义 |
|---|---|---|
| `policy_mode` | `MONITOR_ONLY`（默认）/ `EXPERIMENTAL_POLICY` | 两种都不出许可，只是标注口径 |
| `safety_permit` | **恒 `False`（模块级常量）** | 任何调用方都不许把它当换刀依据 |
| 页面 | `progTag` 追加"· 影子观测" | 值班的人一眼能看到这不是正式判定 |

非法 `POLICY_MODE` 值 → 回退 `MONITOR_ONLY`（不会因为环境变量写错就变成"可上线"）。测试 T2.1~T2.4 守这四条。
