## §3　为什么这不是"参数没调好"：三条机制

| 机制 | 说明 |
|---|---|
| **控制环** | 恒转速（G96/G97）下，为维持转速靠加扭矩 → 磨损/崩刃引起的力变化被搬到**扭矩/电流**上，负载表只剩残余（换刀前后跳变中位 +1.8%，低于件间噪声 3.28%） |
| **判决窗仍太粗** | 本实验最小可用窗是 **2 秒**（数据是突发式上报，更细的窗样本数不够）。崩刃冲击 µs~ms，在 2 秒窗里占 0.05% → 平滑掉 |
| **S/N 结构** | 崩刃是**偶发单次**，而我们的判据基于"末段 vs 稳定段的分布/峰值统计"——**单次事件天然被统计量摊平**；改成"单次事件检测"需要**事件级真值**来调阈值，而我们一次都没有（`NOT_REPRODUCIBLE` #4） |

⚠ **一条必须更正的旧说法**：`66-00` §3 原写"负载表是整数百分比、0.1% 台阶，分辨率不够"。**那是错的**——本导出的 `L_spindle_load` 有 **6824 个不同取值**（中位 1048，最大 31627），**分辨率不是原因**。已在 `66-00` 里改正。

## §4　剩下的两条路（都要外部条件，但第一条可能零开发）

### 4.1 路①：厂商标定报警（推荐先问，可能零开发）

**思路**：不再自己读高分辨率原始值，而是**用 CNC 自己算好的负载监控报警**——FANUC 30i/31i/32i-B 系列内置「负载监控 / 超载报警」功能（负载表 **1~4 ms** 采样，按教学值百分比设阈值）。我们只需要读 **PMC 报警位**（普通 `pmc_read`），不需要高分辨率通道。

| 要问供应商/机床厂的（照抄即可） | 为什么关键 |
|---|---|
| 本机是否开通「负载监控/超载报警」相关选项？ | 决定这条路是否存在 |
| 报警能否输出到 **PMC 位**（A/F 地址）供外部读取？ | 决定我们能否零开发取到 |
| 阈值能否按「相对 Teach/教学值的百分比」设定？范围多少？ | 110~130% 警告 / 140~200% 报警 是常见档位 |
| 内部**判定周期**是多少 ms？报警输出**延迟**典型值？ | 直接决定能不能进 1 秒 |
| 是否支持**分轴**（主轴 + X/Z）分别设阈值？ | 崩刃可能先在某轴上体现 |
| 报警后能否**自动停进给**（或只报警不停）？ | 对应 A 目标的"停机"要求 |

**如果第 1、2 条都是"是"**：我们只需 1~2 人日做 `pmc_read` 轮询 + 落盘，就能拿到**厂商标定过的高频报警**——这条路的性价比高于买振动。

### 4.2 路②：振动/声发射（A3）

`63-00` 已给对比表；D-06 允许提方案、采购另报批。
**在路①没有答案之前，不建议采购**——因为路①可能免费解决，而振动是 1~3 万 + 安装面改造。
