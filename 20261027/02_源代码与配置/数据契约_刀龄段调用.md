# 数据契约：刀龄 / 程序段 / 调用次数（N02 · 审核 P0-02）

> 2026-10-29 整改。产生源：`02_源代码与配置/source/server.py` 的 `run_segments()`（唯一切段实现）
> 与 `compute_view()` 的返回字典；验证：`14_整改执行_v2b/tests/test_i_segment_contract.py`（11 断言）。
> 背景：上一版把 `tool_invocation_index = n_segments`，用"连续程序段数"冒充"刀具调用次数"，
> 且 `segment_id='p'+prog` 无法区分同一程序的第 2 次进入段。本文件是五个标识的**唯一语义定义**。

## 1. 五个标识的语义与来源

| 键 | 语义 | 计算来源 | 可信级别 |
|---|---|---|---|
| `used` | 物理刀龄 = 本起点之后 T1111 参与的**全部程序**件数 | `COUNT(*) FROM pieces WHERE allnum>base`（单 T1111 专用表） | 观测事实 |
| `phys_life_id` | 物理刃口 ID，换程序不变 | `phys_<刀号>_<起点件号>` | 观测事实 |
| `current_program` | 当前主程序号（**原 `segment_id` 的如实含义**） | 最新件的 `prog` | 观测事实 |
| `segment_seq_id` | 第 n 次进入的连续程序段，`s{n}_p{prog}`，同一程序第 2 次进入也可区分 | `run_segments()` 段序 | 观测事实 |
| `program_run_segment_count` | 从起点到现在的**连续同程序段数**（相邻 prog 变化次数 + 1） | `run_segments()` | 观测事实 |
| `tool_invocation_index` | **刀具调用次数：`UNKNOWN`** | 无数据源 | 明确未知 |

## 2. 为什么调用次数只能 UNKNOWN

FOCAS 侧可区分"调用"的信号在本数据中均不可得：
- `L_sub_program` 切削时段为空（见 `09_repro_scripts/s23_dataset_v2.py` 第 14/69 行的同款判定）；
- 刀号恒 T1111，无跳变沿可数；
- 同一程序内同一刀位可能多次调用、一件产品可能含多次切入——**程序段数是调用次数的下界，不是它本身**。

若将来拿到可追溯 FOCAS 调用事件（如子程序调用计数/换刀宏变量），先补采集验证，再把本键从
UNKNOWN 换成真实计数；在那之前，任何对外接口**不得**把段数标成调用次数。
