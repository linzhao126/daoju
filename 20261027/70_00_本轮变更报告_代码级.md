## §2　生产代码逐处（含改前/改后）

### A　`judge_allowed`：样本够 ≠ 有资格判定（P0-MOD-04）

**问题**：原代码 `judge_ok = (m0 is not None and p85 is not None)` 只看历史样本够不够，**不看这把刀的起点是不是人工确认过**。冷启动时 `base_allnum = min_allnum - 1`，件数是"库里这把刀全部件数"，可能横跨好几次换刀。

**改哪儿**：`server.py` L782–790

```python
judge_ok = (m0 is not None and p85 is not None)          # 改前：只这一句，直接用它算 b/h
...
start_confirmed = (last_new is not None)                  # 新增
judge_allowed  = bool(judge_ok and start_confirmed)       # 新增
b = int(np.ceil(BASE_F * m0)) if judge_allowed else None  # 改后：b/h 用新门禁
h = int(np.ceil(EXT_F * m0)) if judge_allowed else None
```

下游三处跟着改（否则会出现"页面说不能判、却仍给了线"）：
- L813 `limit/limit_txt`：未确认时 `limit=None`，文案区分"未标定"与"起点未确认"；
- L833 状态机：`if not judge_allowed: st = "cnt"`（只报件数）；
- L884–886 返回体：`judge_ok` 与 `judge_allowed` **两个字段都返回**，前端才能区分原因。

**结果**：隔离副本服务实测 `judge_allowed=False`、`base_src=cold`、`ref_limit_90=None`。**升级后线上所有刀都会落"只报件数"**——这是故意的，要恢复判定必须在装刀时点一次「换新刀」。

### B　五个标识：把"物理刀龄"和"统计分组"拆开（P0-MOD-03）

**问题**：原来只有 `used` 一个数，看不出"这把刀在哪几个程序上各干多少件"。跨程序时会被当成"换了把刀"。

**改哪儿**：`server.py` L871–876 返回体新增

```python
"phys_life_id": phys_life_id,            # phys_T1111_<base>：物理刃口，换程序不变
"segment_id": "p%d" % prog,              # 当前程序段
"base_segment_id": "p%d" % exposure[0]["prog"],   # 起点所在的程序段
"tool_invocation_index": n_segments,     # 从起点到现在跨过几个连续段
"exposure_by_segment": exposure,         # [{"prog":11,"n":30},{"prog":20,"n":40},...]
```

配套修了 `used` 的 SQL（更早一轮已改，本轮回归确认）：`COUNT(*) FROM pieces WHERE allnum>?`，**不加 `prog` 过滤**。

**结果**：02→03→02（11→20→11，中途未换刀）实测 `used=95`、`exposure` 三段、调用段数 3；旧口径只数最后一段 = 25 件 → 差 70 件。见 `test_g` T2。

### D　`CODE_SHA`：证明"跑的是哪一版"（R09）

**改哪儿**：`server.py` L72–85

```python
def _self_sha():
    return hashlib.sha256(Path(__file__).read_bytes()).hexdigest()[:12]
CODE_SHA = _self_sha()          # 模块加载时算一次
...
"code_sha": CODE_SHA,           # 随 /api/state 返回
```

**为什么不用"文件哈希"**：文件哈希只证明磁盘上那份，分不清内存里跑的那份。启动时算一次并暴露，才能对上"页面上的判定来自哪个版本"。

**结果**：隔离副本服务实测返回 `f336f1d673e0`，与磁盘一致（`s56` → `logs/s56.log`）。

### E　`recv_ts` + `batch_recv_lag_stats()`：把"批次接收延迟"变成可测（R06 P0-a；旧名 `lag_stats`）

**改造三处**（缺一处都算白做）：

1. **建表/迁移** L224、L253、L317–326

```python
CREATE TABLE ... raw_rows(..., feedrate REAL, recv_ts TEXT);
# 老库迁移（放在 z_pos 迁移之后）
if "recv_ts" not in raw_cols:
    c.execute("ALTER TABLE raw_rows ADD COLUMN recv_ts TEXT")
```

2. **写入** L376–394：`write_rows()` 的 INSERT 多一列，取值 `r.get("recv_ts")`（**用 get**，模拟器没有这个字段也不会炸）

3. **打戳** `influx_source.py` L249–255

```python
recv = iso(datetime.now(timezone.utc))   # 这一批被我们拿到的时刻
for r in out:
    r["recv_ts"] = recv                  # 同一批共用一个戳
```

4. **统计** L648–695 `batch_recv_lag_stats()`：取最近 2000 行，`lag = parse(recv_ts) − parse(ts)`，返回 `n / median / p95 / max / min / neg / stale / n_no_recvts`；**负值（时钟不同步）与 >1 天（停机跨天）单独计数并剔除；`n_no_recvts` 为加列前老行的盲区计数**。

**口径必须说清**：戳是"批量写入时刻"，所以 `lag` 是**上界**（含 Influx 查询 + 网络 + 解析）。要拿点值必须在采集盒侧打点。

**结果**：`test_h` 22/22；隔离副本服务实测**老库被补上 `recv_ts` 列**。⚠ 当前 `lag.n=0`（还没有带戳的行）——**这才是"可测"，不是"已有值"**。
