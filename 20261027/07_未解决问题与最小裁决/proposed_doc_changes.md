# 技术方案修改建议（07-4）

> 按任务书 §6.5，凡影响"生命周期/标签/信号映射/模型输出/安全阈值"的变更，须先获批准再实施。

## 一、必须改（不改会持续产生错误结论）

### C1 目标口径：从"正常磨损 RUL"改为分层表述

| 层级 | 建议写法 |
|---|---|
| 主目标 | **换刀时点决策（C2）+ 突发崩刃确认（A）** |
| 研究项 | 到下一次人工换刀的剩余件数（C3-lite），**明确标注非物理磨损** |
| 关闭项 | 物理磨损 RUL（VB 不可得，标 `BLOCKED_BY_METROLOGY`） |

理由：现有材料里"RUL"一词同时指三件事，每次讨论都会绕回同一个歧义。

### C2 基线定义：无条件中位 → 条件剩余寿命

- 现状：`M0 = median(同程序寿命)`，`RUL = M0 − 刀龄`；
- 实测问题：末期系统性低估（N=80 时偏差 −15.3 件），因为"活到 80 件的刀本来就更长寿"；
- 建议：`RUL = median{ L − N | L > N }`（等价 KM 条件中位，无删失时）；
- 实测收益：末期 MAE 17.96 → **14.58**，偏差 −15.29 → **−6.58**，**不依赖任何 FOCAS 特征**。

### C3 线上 HI 与离线 HI 必须区分命名

- 事实：逐件相关 0.17~0.45；离线网格起点接近 x≈0，线上固定 19~40，跨度差约 19 mm；`load_med` 中位差 30~36%。
- 建议：
  - 离线量命名 `HI_xalign`（研究口径）；
  - 线上量命名 `HI_online`（工程口径）；
  - **任何结论必须注明用的是哪一个**；
  - 页面上禁止把 `HI_online` 与历史 `HI_xalign` 结论直接对照。

### C4 `history` 表增加来源标记

- 现状：16 条全部 `src='seed'`，页面显示为"历史换刀记录"；
- 建议：`src ∈ {seed, online, manual}`，展示分列（"在线登记 0 / 离线标定 6"）。

### C5 周期程序归属：首行 → 占比最大

- 现状 `t1111_pipeline.py:1262` 取首行；
- 实测：c27 的 97.5% 是 prog20 却判成 prog14；c34 的 65.9% 是 prog14 却判成 prog19；
- 建议：取行数占比最大的程序；`MinorProgramShare > 5%` 标 `PROGRAM_MIXED` 并在建模时单独处理。

## 二、建议改（提升可审计性）

### C6 UI 六项（见 `05_.../UI修订建议.md`）
D1 文案"必须换"→"需复核"；D2 颜色跟 `limit`；D3 冷启动禁写"新刀"；D4 加噪声带；D5 全库件数标口径；D6 seed/online 分离。

### C7 新增 `predictions` 表（DDL 已在 `02_.../schema/`）
关键字段：`ts_predict`（真实推理时刻）、`data_watermark`、`is_replay`（1=事后回放，不得冒充前瞻）、`calibrated`。

### C8 采集链路加 `recv_ts`
只加一列，就能把"数据到达延迟"从"未知"变成"可测"，是"≤1 秒"的前置。**成本最低、收益最高的一项。**

### C9 台账字段扩充
建议新增：`是否真实失效`、`发现方式`（人工目视/质检/崩刃声）、`崩刃后继续加工件数`、`是否翻刃`（本轮用户已确认"不翻刃"，可固定填 NO）、`尺寸超差值`。

## 三、不建议改（明确保留）

| 项 | 理由 |
|---|---|
| `L_allnum` 当刀龄 | 已证实 9 把刀共用（prog16 实测 86 个增量对应 55 件）；**保持 `COUNT(pieces)`** |
| `0.4 / 0.9 / 1%` 三个阈值 | 目前没有更好的替代；但文案要加"同批调参、未留出验证"的限定 |
| 七区保留策略（raw 7 天 / pieces 30 天 / 水位线 cutoff） | 已避免"放假删库"的坑，不动 |
| 封口延迟 120 秒 | 15 秒拉取 + 120 秒封口是当前唯一稳定配置 |
