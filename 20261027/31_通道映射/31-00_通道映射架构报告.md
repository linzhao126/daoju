## 2　过程中抓到并修掉的三个真问题

这三个都不是"写映射表"能顺带解决的，是**真的会让人白跑一天**的坑。

### 2.1 Python 默认参数在定义时求值（`build_piece_index`）

```python
# 改前
def build_piece_index(raw_csv, cycles=None, cols=COLS):
```

`cols=COLS` 在**函数定义那一刻**就把 L 通道的列名绑死了。运行时改 `HA.COLS` 无效，切到 R 通道报：

```
ValueError: Usecols do not match columns, columns expected but not found:
            ['L_spindle_load', 'L_spindle_speed', 'L_abso_x', ...]
```

同一处还有 `compute_segments(..., metric=METRIC)` 和 `hi_from_segments(..., metric=METRIC)`。

**修法**：默认值改 `None`，函数体内 `cols = COLS if cols is None else cols`。三处都改。

### 2.2 按位置切片取数值列（`build_piece_index`）

```python
# 改前
for c in cols[3:]:                    # 依赖列顺序！
    d[c] = pd.to_numeric(d[c], errors='coerce')
```

`COLS` 顺序一变（映射层会改变顺序），`cols[3:]` 就漏掉 `x` 列、误转 `life_cycle`。**这是原代码的既有脆弱点，改映射时才暴露。**

**修法**：显式按逻辑名列出 `(CH.x, CH.z, CH.load, CH.spd, CH.allnum)`。

### 2.3 适配垫片放错位置（`z0_of` 与 `_xalign_piece` 的列名冲突）

第一版在 `build_piece_index` 之后就把整个 `rows` 改成 L 名，结果 `z0_of` 报：

```
KeyError: 'R_spindle_speed'
```

因为 `z0_of` 用的是**本通道**列名（`CH.spd`），而 df 已被改名。

**修法**：只在**调用 `_xalign_piece` 的那一瞬**转换（`df_in = CH.to_pipeline_names(rows[a]) if CHANNEL!='L' else rows[a]`），不动 `rows` 本身。

### 3.5 四个结构性差异（这是"不能移植"的真正原因）

#### ① X 行程完全不同 —— 最致命

| 通道 | X 全行程 | **落在 [19, 40] 的行占比** |
|---|---|---|
| L（4152） | 0 ~ 233 | 切断段本身就在 19~40 |
| **R（2428）** | **−112 ~ +168** | **0.8% ~ 1.4%** |

`xalign` 的 `X_MIN=19.0 / X_MAX=40.0` 不是"参数偏了"，而是**把 R 通道 99% 的行排除在外**。

#### ② 件划分失效（`allnum` 不可用）

| 周期 | 行数 | 件数（allnum 去重） | allnum=0 占比 |
|---|---|---|---|
| c10 | 71 | 3 | 77.5% |
| **c11–c19** | 4,875 ~ 17,364 | **1** | **100%** |
| c20 | 41,566 | 696 | 87.6% |
| c21 / c22 / c23 | 18,440 / 23,856 / 15,932 | 1,969 / 2,642 / 1,601 | 0% |

**c11–c19 整周期 allnum 全为 0** → 被当成"1 个件"，直接低于 `min_pieces=40`。

#### ③ 门控量语义不同

| 通道 | `spindle_speed > 0` 占比 | 唯一值 | 中位 |
|---|---|---|---|
| L | **52.4%** | 1,771 | 0.0 |
| R | **100%** | 76 | 3,799 |

L 通道靠"主轴转速 >0"剔除非切削行；**R 通道主轴恒转**（定转速 3,799），这个门控完全失效。

#### ④ 主程序语义不同

| 通道 | 主程序取值 | 含义 |
|---|---|---|
| L | 7 个品番程序（`C5G25-02` / `C5G25-03` 两品番） | 主切削工序 |
| R | 3 个值，主体 **`201(SUB KASHIME)`**（副轴夹持），占 99.9% | **不是品番加工程序** |

所以「按品番分组算 M0」这套在 R 通道上根本没有对应物。

## 5　对"公共方案"的实际含义

审核 P1-08 要求"公共方案需通道映射架构"。本轮的实际交付是：

| 层 | 状态 |
|---|---|
| **字段访问**（`L_` → 逻辑名） | ✅ 已解耦，`hi_asof` 零回归 |
| **通道识别**（新设备接入） | ✅ 只凭表头即可判定 |
| **契约校验**（缺字段诊断） | ✅ 可列出缺哪个必需字段 |
| **Z0 标定** | ⚠ 已按通道分表，但 R 通道留空（未标定） |
| **算法参数**（X 行程 / 门控 / 件划分） | ❌ **未解耦**，且这层不是"配置"，是**物理差异** |
| **主流水线 `_xalign_piece`** | ❌ 仍写死 `L_`（需报备后改） |

**所以要诚实地说**：这不是"一套代码跑所有机床"，而是"**字段层已通，算法层仍绑在 4152**"。

**换到 R 通道的真实工作量**（本次实测得出）：

1. 先确定 R 通道的**切削工步判据**——不能靠 `spindle_speed`（恒转），需要别的信号（`R_circle_time`？`R_rate1`？`R_state`？）；
2. 确定**件划分依据**——`R_allnum` 大部分为 0，需查是否有别的件序号（`R_circle_time` 下降沿？）；
3. 重定 **X 窗口**——`−112~+168` 与 4152 完全不同，且 R 通道可能不是"切断"工序；
4. 确认 R 通道测的是**什么工序**（`201(SUB KASHIME)` 说明主体是副轴夹持）。

**在这四件没答案之前，把 R 通道接进来只会产出无意义的 HI。**
