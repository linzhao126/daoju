# 页面 UI 修订建议（P0-05 / P1-04）

> 原则：**宁可显示「—」，也不显示一个会被人当成结论的数。**
> 本轮不改代码，只给变更计划 + 回归测试清单。

---

## 一、必须修（会误导决策）

### D1 状态文案「已过中位寿命，必须换」

- 现状：`index.html:222` `bad:"已过中位寿命，必须换"`
- 问题：M0 是**中位数**，历史上一半的刀在它之上仍在用。中位数不构成安全极限。
- 建议：改为 `bad:"已过同程序中位寿命 · 需复核"`
- 回归：`TXT.bad` 与 `server.py:619-620` 的 `st="bad"` 分支一致；页面截图核对。

### D2 颜色跟固定 `h`，文字跟 `limit`

- 现状：颜色 `used >= h` 变橙红（`server.py:621-622`）；文字按 `limit`（`index.html:381`）
- 问题：`granted=False` 时文字说"第 b 件就换"，颜色要到 `h`（≈0.9M0）才变，**相差 0.5×M0 ≈ 50 件**
- 建议：状态机改为 `used >= (limit or h)`，让颜色反映"该在哪件换"这个权威答案
- 回归：`granted=None/True/False` 三种情况下 b/h/limit 与颜色的一致性表

### D3 冷启动仍显示「比新刀高 0.7%」

- 现状：`index.html:366` `"（比新刀 " + dir + " " + pct + "%）"`
- 问题：`base_allnum = min(allnum) − 1`，前 20 件**不是物理新刃的前 20 件**，可能是旧刀中段
- 建议：`base_src=cold` 时改为 `"（相对本观测段参考基线 +0.7%）"`；只有 `base_src=event` 才允许出现"新刀"字样
- 回归：`base_src` 两态 × `hi=None/有值` 共 4 种组合的文案快照

### D4 HI 显示三位小数但没有噪声带

- 现状：`HI 1.007`，文案"高 0.7%"
- 事实：单件 σ≈1.95%，10 件中位后 ≈0.6%，**0.7% ≈ 1.1σ，单侧 p≈0.14，不显著**
- 建议：显示 `HI 1.007（噪声带 ±0.006）`；`judge_ok=False` 时把信号行折叠进"详情"
- 回归：噪声带数值随 W 变化；W=10 时显示 0.006

### D5 「已封口 100 件」口径不明

- 现状：`pieces_total = COUNT(*) FROM pieces`（**全库**，不分程序），与「本把刀 ≥55 件」并列展示
- 实测：prog16 55 + prog17 45 = 100
- 建议：改为 `"全库已封口 100 件（本程序 55）"`，并加 tooltip
- 回归：两程序同时有数据时，两个数字都要对且不相等

### D6 `history` 的 seed 与 online 混在一起

- 现状：`history` 表 16 条全部 `src='seed'`（来自离线 `xalign_HI.csv`），页面显示为"历史换刀记录"
- 问题：把"离线实测"说成"在线登记"
- 建议：SQL 加 `src` 过滤/分组；页面写 `"历史 6 条（其中在线登记 0 条，离线标定 6 条）"`
- 回归：`src` 三种取值（seed/online/manual）分别显示

## 二、建议修（不影响判定，但影响信任）

| # | 项 | 建议 |
|---|---|---|
| D7 | 进度条分母 `span` | 现在无历史时 `span = max(used×1.25, 100)`，55 件恰好显示 55%，容易误读为"55% 寿命"。建议加刻度标注或改为"件数条"而非"进度条" |
| D8 | `EXP_M0=100` | 页面已标"不是判定依据"，但没有说明 100 的来源（prog14 M0=89.5 / prog20 M0=105.5 合并取整）。建议在 tooltip 里写清 |
| D9 | 程序号切换 | `current_prog()` 取最新一件的 prog。c33/c34 这类跨程序周期会让 M0 突然换组 → 建议加"程序混合"标记 |
| D10 | 数据新鲜度 | 三分支（正在计算/无新数据/拉取异常）已有；建议补第四态："水位线停滞 > 24h"，因为本轮实测库停在 10-22 而今天 10-27 |

## 三、回归测试清单（改完后必须跑）

```text
R1  n_hist = 0        → 四格全「—」、state=cnt、不显示"新刀"字样
R2  n_hist = 3        → 前三格有数、第四格「—」、judge_ok=False、state=cnt
R3  n_hist = 5        → 四格全有数、b/h 出现、state 按件数走
R4  base_src=cold     → 件数显示 ≥N、HI 文案用"本观测段参考基线"
R5  base_src=event    → 件数精确、可用"新刀"字样
R6  granted=False     → 文字"第 b 件换"与颜色档位一致（D2 修完后）
R7  granted=True      → 文字"可用到 h"、颜色在 b 处变
R8  pieces_total      → 两程序并存时，全库数 ≠ 本程序数，且两者都正确
R9  history 含 seed   → 显示"在线 0 / 离线 N"
R10 水位线停滞 4 天   → 体检条显示"水位线停滞"，不是"连接正常"
```

## 四、变更影响评估

| 项 | 改哪 | 风险 | 是否需评审 |
|---|---|---|---|
| D1 | `index.html` 一行常量 | 低 | 否 |

| D3 | `index.html` 文案分支 | 低 | 否 |
| D4 | `index.html` + 前端计算噪声带 | 低 | 否 |
| D5 | `server.py` 返回字段 + `index.html` | 低 | 否 |
| D6 | `server.py` SQL + DB 加 `src` | **中**（需迁移，注意 ALTER 顺序） | 是 |
| D7~D10 | 展示层 | 低 | 否 |

**D2 与 D6 属于"影响判定语义/数据模型"的变更**，按任务书 §6.5 必须先提交 `proposed_doc_changes.md` 并获批准，本轮未改。
