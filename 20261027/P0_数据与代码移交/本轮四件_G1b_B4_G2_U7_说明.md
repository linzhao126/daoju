## 三、U-7：反事实泄漏探针 —— V1/V2 干净，**V3 有实质差异**

对 s53/bt_core 的**真实口径**做三种反事实，80 个有效对照格：

| 检验 | 结果 | 判定 |
|---|---|---|
| **V1** 把第 N 件之后的 HI 全部置 NaN 再预测 | 四个模型最大偏差 **0.0000**（80 格） | ✅ 通过 —— 没有偷看被评估刀的未来输入 |
| **V2** 把被评估刀自身完整寿命扰动 ±20% | `FitB`/`FitG` 偏差 **0.0000**（160 对照） | ✅ 通过 —— `bt_core` 两层留一的承诺成立，无标签泄漏 |
| **V3** 训练池只保留"k 跑到第 N 件时**已经换完刀**"的刀（模拟在线真实可得性） | 平均偏差 **M0A/M0B 7.70 件**、**M1Old 12.30 件**、**M1New 7.91 件**；最大 21.5 / 56.3 / 46.0 件 | ❗ **有差异：离线指标偏乐观** |

**V3 的含义（这条比 MAE 数字本身重要）**：站在"k 刚跑完第 N 件"的时刻，那些当时**还没换刀**的刀，其完整寿命在真实在线场景是**未知的**；把它们剔掉后，训练池**平均缩水 41.5%**（中位 40%）。

所以：
- 现有回测的 `MAE≈13.57 / 9.44` 是**离线口径**（训练池用了"事后才知道"的完整寿命）
- 上线后同一时刻能用的训练刀**不到六成**，预测会漂 **约 8~12 件**
- 这不是 bug，是必须写进验收前提的结构性差距 → **已列为待 0 号位知晓项 F8**
- 顺带说明：`HI_merged_28.csv` 未存时间列，V3 的"时刻"用了 **allnum 件时钟**（机床全局递增计数，与时间同序），已在脚本 docstring 声明

## 四、B4：采集质量体检 —— 顺带推翻了两处旧假设，也暴露两个自己的 bug

**跑的过程里抓到两个自身缺陷**（都改了）：
1. **时间戳单位**：`pd.to_datetime` 在混合格式下可能给 `datetime64[us]/[s]`，我却一律 `/1e9` → 中位间隔被算成 0.0 s、"重复时戳"恒为 0。已改为显式 `as_unit('ns')`。
2. **行间隔 ≠ 轮询周期**：行是**成批写入**的（实测行间隔中位 **0.02 s**、P95 **0.98 s**），只测行间隔无法回答"多久采一次"。已补 2/5/10/16/30 s 档做 burst 边界（>1 s 视为 burst 切分）重跑。

**当前已确认的事实**：

| 项 | 值 |
|---|---|
| 总行数 | 8,200,664（4152 全通道） |
| 时间乱序 / 完全重复时戳 | **0 / 0** |
| `_time` 解析失败 | 0 |
| **行间隔分布** | 中位 **0.02 s** · P75 0.05 s · **P95 0.98 s** · P99 1.02 s · 均值 0.43 s |
| **burst 边界档（>Ns 段数）** | >2 s **21,470** · >5 s 9,612 · >10 s 4,787 · **>16 s 3,038** · >30 s 1,953 · >1 min 657 · >5 min 54 · >1 h 6 · >6 h 4 · >24 h 2 |
| `L_state` 分布 | 3（切削）3,222,511 行 · 4（非切削）4,971,550 行 · 0/1/5 合计约 6.6k 行 |
| 最长 4 段空档 | 09-30 17:31 → 10-09 15:58（**214.5 h**）· 10-09 16:15 → 10-14 09:42（**113.5 h**）· 09-28 23:59 → 09-29 15:45（15.8 h）· 09-22 23:59 → 09-23 15:11（15.2 h） |
| allnum 连续性 | 各刀**回退≈0**（计数器单调，未见人工清零）；跳号 0~90/刀；缺号数 0~3,050/刀（如 T1111 跳号 75 次、缺号 1,462 件次） |

**由数据得到的两个结论（推翻旧假设）**：

1. **实际行时间分辨率约 1 s**（P95=0.98 s），**不是旧文档里的 15 s 轮询**。>16 s 的跳变只有 3,038 次，说明不是周期性 15 s 拉取，而是**连续流式入库 + 偶尔长静默**。→ N05 里“15 s 轮询 + 120 s 封口 = 135 s 预算”的两个构成数**均无实测支撑**，必须标为“假设值”而非实测；对 4152 RUL 不影响（仍按件/周期聚合），但对日后崩刃时延预算是关键修正。
2. **两段 9 天 / 4.7 天的空档正好卡在旧批与新批的接缝**（09-30→10-09、10-09→10-14）——与“旧 labeled 覆盖 c25~c47、新 labeled 覆盖 c48~c60”的分批事实吻合，即**这两段不是采集中断，而是两次独立导出的时间边界**；但 15.8 h / 15.2 h 那两段发生在批次内部（且总在 23:59:59 断开），**更像导出截断而非停产**，应列入 C4 向现场确认。
3. 另：`L_state=4`（非切削）行数比 `=3`（切削）还多（4.97M vs 3.22M），**约 60% 的行不在切削态**——这支持“用整件均值会把大量非切削时间平摊进去”的旧判断，也提示件级特征应先按 state=3 筛段。（本条已归入文档与脚本注释，未改 N05 历史正文，待你确认后一并改）
