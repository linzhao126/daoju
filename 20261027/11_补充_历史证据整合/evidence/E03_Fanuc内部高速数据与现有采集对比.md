# Fanuc 内部高速数据 vs 我们现在采集的数据

> 回答用户问题："Fanuc，采样频率 62.5Hz 是车床内部的最高频率吗？"
> 生成时间：2026-09-11
> 依据：FANUC 官方手册 B-65404EN（Servo Guide Operator's Manual）、B-65285EN/04、
> A-79087EN（16i/18i/21i Servo Guide Mate Specification）、A-53866E（Basic Spindle Tuning using Servo Guide）
> 以及本工作区 236 万行实测数据的统计

---

## 0. 一句话结论

**不是。62.5Hz 是我们"这一路采集"的极限，不是 Fanuc 的极限。**

- Fanuc 内部伺服数据官方最快可达 **62.5 μs = 16 kHz**（比现在快 **256 倍**）
- 主轴最快 **500 μs = 2 kHz**（取决于主轴型号）

**但更重要的一件事：真正的瓶颈可能不是频率，而是"我们采的是哪一类数据"。**
即使维持 16ms 不变，只要把读取地址换成 Fanuc 内部的连续物理量，
分辨率就能提升约 **2 个数量级**——这可能不需要购买任何硬件。

## 1. Fanuc 官方规格（有据可查，不是我的估计）

### 1.1 Servo Guide 的采样周期选项

Servo Guide 是 Fanuc 官方的伺服/主轴调试诊断工具，通过以太网（或 HSSB）连接 CNC。

**伺服轴**（可任选其一）：

| 采样周期 | 等效频率 | 通道数限制 |
|---|---|---|
| **62.5 μs** | **16 kHz** | 每个 DSP 仅 1 通道，整个 NC 最多 2 通道 |
| **125 μs** | **8 kHz** | 每 DSP 最多 2 通道，整个 NC 最多 4 通道 |
| 250 μs | 4 kHz | 每 DSP 最多 4 通道 |
| 500 μs | 2 kHz | — |
| 1 ms | 1 kHz | — |
| 2 / 5 / 10 / 20 / 50 / 100 ms | 500~10 Hz | — |

**主轴**：

| 主轴类型 | 可选采样周期 | 最快频率 |
|---|---|---|
| **αi 主轴**（新 SIC 模式，诊断参数 No.400 第 7 位 = 1） | 500 μs ~ 100 ms | **2 kHz** |
| **α 主轴**（旧型号） | **只能 8 ms** | 125 Hz |
| αi 主轴（旧 SIC 模式） | 8 ms | 125 Hz |

> **务必到现场确认你们这台机器的主轴是 α 还是 αi、以及 SIC 模式。** 若是 α 主轴，
> 主轴侧的频率上限就只有 125Hz（和我们现在的采样率同量级），此时**只能靠伺服轴侧**。

### 1.2 Fanuc 内部可以测到的连续物理量（我们目前一个都没拿到）

**伺服轴**（Servo Guide 标记为 † 的支持高速采样）：

| 数据名 | 含义 | 为什么重要 |
|---|---|---|
| **`TCMD`** | 扭矩指令 | 伺服电机实际输出的扭矩，未经过百分比量化 |
| **`DTRQ`** | **估算扰动扭矩** | ⭐ **最关键**——见下文 Fanuc 自己的专利 |
| `IR` / `IS` | 电机电流（两相） | 真正的电流原始值 |
| `IEFF` | 有效电流 | |
| `IQ` | 有功电流 | |
| `ERR` | 位置偏差（跟随误差） | 间接反映切削阻力 |
| `POSF` | 位置反馈 | |
| `VCMD` / `SPEED` | 速度指令 / 实际转速 | |
| `MTTMP` | 电机绕组温度（℃） | |

**主轴**：

| 数据名 | 含义 | 量纲 |
|---|---|---|
| **`DTRQ`** | **主轴负载扭矩（估算扰动扭矩）** | 16384 = 100% 最大电机扭矩 |
| `LMDAT` | 负载表数据（等价于 SPM 的 LM 端子电压输出） | 32768 = 10 V |
| `TCMD` | 扭矩指令 | 16384 = 100% |
| `FREQ` | 扰动扭矩频率（Hz） | |
| `MTTMP` | 电机绕组温度（℃） | 分辨率 1 ℃ |

## 2. 决定性论据：Fanuc 自己的专利就是这么做的

> **Fanuc Ltd. 专利 US5602347：
> 「Tool life control method based on disturbance load torque of motor」
> （基于电机扰动负载扭矩的刀具寿命控制方法）**

专利描述的流程（原文摘要）：

1. 每个**速度环处理周期**，CNC 内部计算 `estimated disturbance load torque Td2`
   （估算扰动负载扭矩，已扣除摩擦扭矩分量）
2. 该值被写入 **common memory**（公共内存）
3. **PMC 处理器**（比速度环周期长的周期）定期读取 Td2
4. 与设定参考值 `Ts` 比较，若超过且持续设定时间 → **判定刀具寿命已到**

**这意味着三件事：**

1. Fanuc **官方认为**扰动负载扭矩可以反映刀具状态，并为此申请了专利
2. 这个量在 CNC 内部**一直在算**，每个速度环周期更新，不是我们要凭空造出来的
3. 它在 CNC 画面/诊断接口里是存在的（Servo Guide 可以直接看波形）

**所以：CNC 内部存在能反映刀具状态的数据，这已经不是假设，而是 Fanuc 写在自己的专利里的。**

我们之前之所以找不到信号，很可能是因为我们拿的是**被二次加工并量化成整数百分比之后的"负载表显示值"**，
而不是这些原始的扭矩/电流/扰动量。

## 3. 实测：我们现在的数据到底损失了多少

读取装备 T1111 的实际切削行（主轴转速 > 100，共 69,437 行）统计：

| 通道 | 是否整数 | 步长 | P1 ~ P99 实际范围 | **相对分辨率** |
|---|---|---|---|---|
| `L_spindle_load` | 是 | 1 | 509 ~ 7250 | **0.015%**（很好） |
| `L_X_servo_load` | 是 | 1 | 11 ~ 47 | **2.8%** |
| `L_Y_servo_load` | 是 | 1 | 16 ~ 23 | **14%** |
| `L_Z_servo_load` | 是 | 1 | 3 ~ 5 | **33 ~ 50%** |
| `L_A` / `L_B` / `L_C` / `L_E`_servo_load | 是 | 1 | 几乎恒为 0 | **无用** |

**关键判读：**

- 所有伺服负载通道都是**整数百分比**，最小步进就是 1
- 但实际切削时它们只在极窄的区间里活动：Z 轴只有 3~5 这么几个台阶
- **刀具磨损引起的伺服力变化通常只有百分之几**——它比量化台阶还小，
  直接被"取整"丢掉了

**结论：信息在"变成整数百分比"这一步就已经丢失了，跟采样快慢无关。**

对比一下量纲：

| 我们拿到的 | Fanuc 内部的 |
|---|---|
| `L_X_servo_load`（整数，1% 一跳） | `TCMD` / `DTRQ`（16384 = 100% → 分辨率 **0.006%**） |
| 单轴可用台阶 2~36 个 | 连续值，台阶数 16384 |

**这就是约两个数量级的差距——不需要提高采样率就能拿到。**

## 4. 回答："62.5Hz 是内部最高频率吗"

| 说法 | 是否正确 | 说明 |
|---|---|---|
| "Fanuc 内部最高只有 62.5Hz" | ❌ **错** | 伺服轴官方可达 16 kHz（62.5 μs） |
| "现在的导出受限于 62.5Hz" | ✅ **对** | 但我们看到的 16ms 是**采集网关侧的轮询/落库间隔**，同时也是"负载显示值"本身的更新节奏 |
| "要提高就必须买高速采集卡" | ⚠️ **只对一半** | 若是外接传感器，需要；**但若改读 CNC 内部地址，不需要买卡** |

### 三层对比

| 层 | 数据 | 频率 | 我们有吗 |
|---|---|---|---|
| **CNC 内部控制** | 扭矩指令、扰动扭矩、电流、位置偏差 | 62.5 μs ~ 1 ms（16 kHz ~ 1 kHz） | ❌ **没有** |
| **网关/导出侧轮询** | 我们看到的 16 ms 间隔 | 62.5 Hz | ✅ 这是限制之一 |
| **数据种类** | 整数百分比负载显示值 | — | ❌ **这才是主要瓶颈** |

## 5. 落地：零硬件成本的验证方案

### 步骤 1 — 现场确认三件事（10 分钟）

| 要确认的 | 怎么看 | 为什么重要 |
|---|---|---|
| **CNC 系列型号** | SYSTEM 键 → 系统/版本画面（0i-B/C/D、16i/18i/21i、30i/31i/32i…） | 决定 Servo Guide 能否支持、采样率选项 |
| **是否含 Servo Guide / Servo Guide Mate 选项** | SYSTEM 键 → 连续按右扩展软键 → 看有没有 **[S-GUID]**；或看能否从 PC 连 Servo Guide | Mate 版本嵌在 CNC 里，不用外接 PC |
| **是否含"异常负载扭矩检测功能"选项** | 问 Fanuc 代理商 / 查功能清单 | ⚠️ 手册原文：*For data output, the option of the unexpected disturbance torque detection function is required* —— **DTRQ 输出可能需要额外选项** |

### 步骤 2 — 一次性标定实验（半天，零采购）

不需要长期改造，先在一把刀上做一次：

1. 换上新刀（第 1 次调用），用 Servo Guide 抓一组波形：
   - 伺服通道：`TCMD`、`DTRQ`、`ERR`
   - 主轴通道：`DTRQ`、`LMDAT`
   - 采样周期选 **1 ms**（兼顾通道数与数据量），或 500 μs
2. 同一把刀用到**寿命中段**（约 60 次调用）、**临换刀前**（末段）各再抓一组
3. 对比三组的**均值 / RMS / 峰度 / 频域主峰位置**

**判据（和之前一致，防止自欺）**：只看相对变化够不够大——
若中段、末段的 `DTRQ` 相对新刀有 **≥10% 的稳定偏移且各周期方向一致**，才有继续的意义。

### 步骤 3 — 若有效，再谈如何长期获取

| 方式 | 适用 | 成本 |
|---|---|---|
| Servo Guide 临时抓波形 | **只适合做标定实验**，不适合 7×24 | 只要软件 + 网线 |
| FOCAS2 / 第三方 SDK 开发 | 长期连续采集，可按需取指定地址 | 软件开发 |
| Fanuc MT-LINKi 等产品 | 成品化的机床数据采集 | 商业授权 |
| 让现有采集供应商改读地址 | **最省事**——问他们能否把读的地址从"负载百分比"换成 TCMD/DTRQ | 取决于供应商能力 |

## 6. 必须说清的限制与风险（不要过度乐观）

1. **选项可能没买**：`DTRQ` 输出需要"异常扰动扭矩检测功能"选项。
   若没有，就只能用 `TCMD`（扭矩指令通常不需要额外选项即可测量）。
2. **主轴型号决定上限**：若是 α 主轴（旧），主轴侧最快只有 8 ms。**伺服轴不受这个限制**。
3. **Servo Guide 不是生产设备**：它是调试工具。要长期跑，得走 FOCAS/SDK 或商业产品。
4. **即使拿到 TCMD/DTRQ，也不能保证一定有信号**——但值得一试，因为成本几乎为零，
   而且 Fanuc 自己的专利表明这条路在物理上是成立的。
5. **另一层顾虑：这台机加工高度标准化**（转速差 0.5%、负载差 2%），
   说明控制回路确实很强。它到底能不能"压不住"磨损带来的变化，需要数据说话，不能靠推理。

## 7. 与前一轮结论的关系（重要修正）

前一轮我说"带宽上限 31Hz 是硬瓶颈"，现在需要精确化为两件不同的事：

| 场景 | 结论 |
|---|---|
| **外接振动 / 电流互感器** | 接进现有 62.5Hz 盒子仍然完全无效 —— **此结论不变** |
| **改读 CNC 内部地址** | **要拆成三层看，不能一概而论** —— "读哪些地址"不换硬件就能改（最该先做）；"读多快"才可能受盒子固件约束。详见《采集链路与CNC内部参数说明.md》 |

同时**降级但不排除**此前的其他出路：
工件质检数字化（仍是绕开①层的根本办法）、Weibull 换刀决策（零投入、已出数）、
便携显微镜测 VB（给模型补真标签）。
