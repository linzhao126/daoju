**踩过一次坑**（记录在案，防止下次复现同样的假阳性）：v1 版姓名规则写成 `^[\u4e00-\u9fa5]{2,4}(?=,|$)`，把 CSV 每行的首列"副轴"当成姓名，误报 50 处，整体判"禁止公开"。**"全绿"和"全红"都要先看命中样例再下结论**。

**结论**：无个人标识。剩余敏感性全部是"产线工艺信息"（设备号、刀号、道具型号、班产、寿命），不是个人信息。

## §4　措施：让包能独立跑（路径解耦）

此前 7 个读台账的脚本全部写 `XLS = os.path.join(ROOT, '三厂换刀记录.xlsx')`，`ROOT` 是仓库根 → **把 `20261027/` 这个包单独拷走就报 FileNotFoundError**，等于台账虽然"在包里"，实际数据流仍依赖包外文件。

改为**包内副本优先、仓库根回退**（每个脚本 4 行，不新建共享模块，避免再多一个依赖点）：

```python
BASE = os.path.dirname(os.path.dirname(os.path.abspath(__file__)))   # .../20261027
XLS = os.path.join(BASE, '15_台账真值检验', 'input', '三厂换刀记录.xlsx')
if not os.path.exists(XLS):
    XLS = os.path.join(ROOT, '三厂换刀记录.xlsx')
```

| 脚本 | 包内优先 | 残留硬编码旧目录 |
|---|---|---|
| s30 / s31 / s32 / s33 / s34 / s40 / s42 | **7 / 7** | **0 / 7** |

SHA256 三方对账（`ledger_sha256.txt`）：

```
包内副本    3391bb65…97649  15483 B
仓库根原件  3391bb65…97649
MANIFEST_v2 3391bb65…97649
一致：是
```

## §5　顺带修掉的一个交付级缺陷（审核没提，但这轮自查发现）

**现象**：`15_台账真值检验/switch_detect_metrics.csv` 在交付目录里一直是 10-27 19:56 的版本，写着 `AUC_gap = 0.8618`、`召回率 0.9474`、`精确率 0.0103`；而 15-00 报告正文写的是 `AUC 0.560`。同一份包里数字自相矛盾。

**根因**：`s30` 第 40 行把输出目录写死成 `ROOT/20261026/恢复/20261027/15_台账真值检验`。10-28 11:08 用户把目录 `恢复` 改名为 `回复` 之后，这个路径指向一个**不存在的目录**，`os.makedirs` 又把它**重新创建出来**——于是修正后的结果全写进了僵尸目录 `20261026/恢复/`，交付目录里留的仍是审核判定为循环论证的那一版（TP 来自 `life_cycle`）。

**处置**：

1. `s30` 改为相对 `__file__` 定位（`BASE/15_台账真值检验`），重跑；
2. 交付目录内 6 个 CSV 更新为 10-29 10:35 版本，`AUC_gap = 0.5599`、`召回率 1.0`、`精确率 0.07`，与 15-00 一致；
3. 僵尸目录重命名为 `20261026/_废弃_恢复_20261029_路径写死残留/`（7 个文件，**未删除**，用户确认后可手工清理）。

**教训**（已同步到 §4 的写法约束）：凡是"输出目录"，一律不许出现绝对路径或目录名字面量；凡出现，就必须有一次"跑完检查文件 mtime"的动作，否则改名/搬移类操作会让旧结果静默冒充新结果。
