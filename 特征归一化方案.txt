【0. 一句话结论】
  XGBoost 等树模型: 这 265 列【一列都不需要】做标准化/归一化。
    树的分裂只看排序, 任何单调缩放不改变分裂结果。
  但下面 3 类归一化与模型无关, 不做会出事:
    (1) 物理量纲归一化 -- 把绝对量换成相对量(核心: 绝对坐标/负载/转速)
    (2) 跨周期/跨机床分布对齐 -- 你最终要迁移到别的车床, 这是必须的
    (3) 换模型时才需要 -- LSTM/TCN/SVM/KNN/线性/PCA 必须 z-score 或 [0,1]

【6. 归一化决策表: 你的场景该做哪一项】
==============================================================================

  场景A: XGBoost / LightGBM / CatBoost / 随机森林 (树模型)
    -> 标准化(z-score): 不需要, 做了也不涨点
    -> 归一化([0,1])  : 不需要
    -> 物理相对化    : 建议做(见第7节), 为的是跨周期/跨机床可比, 不是为树模型
    -> 必须处理的    : slope 列的 NaN; 常量列(已在黑名单)

  场景B: LSTM / TCN / Transformer / MLP (神经网络)
    -> 必须 z-score(或用 RobustScaler, 你的数据离群点很多)
    -> 且 scaler 只能在 train 上 fit, 再 transform val/test
    -> 目标 y 也要缩放(rul_hour 跨周期差 52 倍, 强烈建议换用百分比标签)

  场景C: SVM(RBF) / KNN / 岭回归-Lasso / PCA / 基于距离的特征选择
    -> 必须标准化, 否则 range 大的列完全支配距离/惩罚项

  场景D: 迁移到其它车床(你的最终目标)
    -> 必须做【分位数对齐 / per-machine 标准化】
    -> 原因见 demo_quantile_align.py 的演示: 同一物理状态在不同床上读数差 30%
    -> 树模型也受益: 对齐后才不会靠'绝对水平'认机床

【7. 建议做的工程归一化(与模型无关, 为可比性和可迁移性)】
==============================================================================

  7.1 绝对坐标 -> 相对坐标  【必做, 优先级最高】
      问题: L_abso_x/y/z 零点随对刀点/工件坐标系变化, 绝对值不可比
      做法: 用滑窗内的相对位移替代绝对值, 例如
            abso_rel = 当前值 - 该行所在滑窗(如5min)的均值
            或: 当前值 - 本 life_cycle 首个采样值
      注意: 只能在 train 段内计算基准, 不能用到全量统计(防泄漏)

  7.2 负载 -> 相对额定负载  【建议做】
      做法: load_norm = 原始负载 / 该轴的 P99 分位
      理由: 不同轴(X/Y/Z/B/C)量程不同, 主轴负载还受功率标定影响
      P99 必须用 train 段算, 存进配置文件, 推理时复用

  7.3 转速 -> 相对最高转速  【建议做】
      做法: speed_norm = L_spindle_speed / 该机床最高转速(常数)

  7.4 跨分布对齐(迁移时)  【最终必做】
      做法: 分位数映射 rank-based:
            x_aligned = Quantile(train_machine distribution, rank of x in its own machine)
      即: 先算 x 在自己机床历史数据中的百分位 r, 再取训练集机床的第 r 百分位值

  7.5 目标变量 y  【强烈建议】
      现状: rul_hour 跨周期量纲差 52 倍(cycle5 总寿命1.3h, cycle3 68.1h)
      建议: 主目标改用 life_used_pct_cut (0~100, 天然归一化)
            或 per-cycle 归一化 rul_pct = rul_hour / 该周期总寿命

  7.6 退化列直接剔除  【必做, 优先级同 7.1】
